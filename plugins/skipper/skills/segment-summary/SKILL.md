# 정리예시 — 연도별·분기별 부문 매출액 및 비중

두 개 표를 만든다.

1. 연도별 매출액 및 비중 (기본 5개년)
2. 분기별 매출액 및 비중 (기본 5개 분기, **단일분기 기준**)

이 스킬은 두 단계다. 초안을 만든 뒤 **공시 원문 표로 검증·보정**하는 것이 본체다.
XBRL 부문 팩트를 그대로 믿으면 안 되는 이유가 두 가지 있다.

- **커버리지가 기업·시점마다 다르다.** 부문 태깅이 아예 없는 기업, 연도만 있고 분기가
  없는 기업, 최근 보고서만 있는 기업이 섞여 있다. 게다가 팩트 적재가 진행 중이면
  **초안이 비어 있어도 그 기업에 부문 공시가 없다는 뜻이 아니다** — 아직 안 들어온
  것일 수 있다.
- **값이 틀릴 수 있다.** 보고서마다 다른 표에서 값이 뽑히거나, 내부거래 제거 열이 부문
  값으로 들어오는 사례가 확인됐다(아래 음수 경고 참조).

따라서 초안이 비었든 채워졌든, **원문 표 대조는 건너뛰지 마라.**

합계와 비중은 렌더링 단계에서 계산한다. JSON에 직접 넣지 마라.

## 1단계 — 초안

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/build_segment_summary.py" "<회사명 또는 종목코드>" \
  --draft draft.json --years 5 --quarters 5
```

표준출력에 연도·분기 기간, 부문 후보, 채워진 칸 수가 찍힌다. 분기 값은 3개월 팩트가
있으면 그 값을, 없으면 누적에서 직전 누적을 빼 단일분기로 환산한다.

### `경고: 누적 차감 결과가 음수라 폐기한 칸이 N개입니다`가 뜨면

보고서마다 부문 표의 범위가 다르게 태깅됐다는 뜻이다. 이 경우 **분기 표는 XBRL로
만들 수 없다.** 폐기되지 않고 남은 분기 값도 같은 이유로 틀렸을 수 있으므로,
전부 버리고 원문 표에서 다시 읽는다. 매출은 음수가 될 수 없다.

## 2단계 — 검증과 보정

`draft.json`을 읽고, 아래를 **직접 확인해서** 값을 채운다.

1. `list_disclosures(ticker, category='정기공시')`로 대상 보고서를 잡는다.
2. 각 보고서에 `get_document(rcept_no, section='매출')`로 "4. 매출 및 수주상황"
   표를 연다. 여기 없으면 `section='주요 제품'`을 본다. `skipper:raw-segment`를
   먼저 돌렸다면 그 CSV에 두 섹션이 이미 들어 있다.
3. 표의 **부문 구분이 초안의 부문 후보와 다르면 원문을 따른다.** 초안의 부문명은
   XBRL 태그에서 왔는데, 이게 회사가 쓰는 사업부문과 아예 다른 표인 경우가 있다 —
   SK(주)는 원문이 투자부문·사업부문 2개인데 XBRL 멤버는 SK이노베이션·SK텔레콤 같은
   종속회사별로 잡힌다. 이럴 때는 초안의 `segments`를 통째로 갈아엎는다.
4. 표마다 **연결/별도 기준과 단위(백만원·천원)를 확인**하고 백만원으로 맞춘다.
5. 분기 값은 단일분기로 환산한다:
   - 1분기보고서 = 1Q 단일
   - 반기보고서 = 상반기 누적 → **2Q 단일 = 반기 − 1Q**
   - 3분기보고서 = 9개월 누적 → **3Q 단일 = 누적 − 반기**
   - 사업보고서 = 연간 → **4Q 단일 = FY − 3Q누적**
   - 표에 "3개월"(당분기) 병기 열이 있으면 환산하지 말고 그 값을 쓴다.
6. 확인되지 않은 칸은 **null로 남긴다.** 추정값을 넣지 마라. 실제로 0인 칸에만
   0을 넣는다 — null과 0은 다르게 처리된다.
7. 근거 보고서를 `sources`에 `{"title": ..., "rcept_no": ...}`로 채운다.
8. 보정을 마쳤으면 `_주의` 키는 지운다.

## 3단계 — 렌더링

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/build_segment_summary.py" "<회사명>" --data draft.json
```

## JSON 형태

```json
{
  "company": "SK",
  "ticker": "034730",
  "unit": "백만원",
  "annual": {
    "periods": ["2021", "2022", "2023", "2024", "2025"],
    "segments": { "투자부문": [1000000, 1100000, null, 1250000, 1300000] }
  },
  "quarterly": {
    "periods": ["25.1Q", "25.2Q", "25.3Q", "25.4Q", "26.1Q"],
    "segments": { "투자부문": [300000, 320000, 330000, 350000, 340000] }
  },
  "sources": [{ "title": "사업보고서 (2025.12)", "rcept_no": "20260318001157" }]
}
```

## 합계·비중 규칙

**어느 한 부문이라도 값이 비면 그 기간의 합계와 비중은 비워둔다.** 부분합을 합계로
쓰면 비중이 100%로 부풀어 그대로 오독되기 때문이다. 그래서 한 기간을 완성하려면
그 기간의 모든 부문 값이 있어야 한다.

## 보고할 때

- 채워진 칸 수와 빈 칸을 명시한다. 빈 칸은 "원문에서 확인되지 않았다"는 뜻이지
  0이 아니다.
- 각 수치의 근거 보고서(접수번호)와 연결/별도 기준을 함께 적는다.
- 분기 값을 차감으로 환산했다면 산식을 밝힌다.

## 실패 처리

- `--draft 또는 --data 중 하나를 지정하세요` → 1단계부터 다시 한다.
- 초안의 부문 후보가 0개여도 정상이다. 그 기업은 XBRL 부문 태깅이 없다는 뜻이므로
  2단계에서 원문 표만으로 부문을 정의해 채운다.
