# Raw_BSPL — 보고서별 연결재무제표 원자료

정기보고서마다 "2. 연결재무제표"의 네 개 표를 통째로 뽑아 옆으로 나란히 붙인
CSV를 만든다. 보고서를 옆으로 붙이는 이유는 **같은 계정이 보고서마다 다르게
보고될 수 있기 때문**이다 — 재작성(restatement)을 눈으로 잡으려면 기간별 최신값
하나가 아니라 보고서별 as-reported 값이 필요하다.

## 실행

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/build_raw_bspl.py" "<회사명 또는 종목코드>" \
  --reports 4 --fs-div CFS --unit 백만원
```

옵션:

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--reports N` | 4 | 최신순으로 붙일 보고서 개수 |
| `--fs-div` | `CFS` | `CFS`=연결, `OFS`=별도, `both`=둘 다 |
| `--unit` | `백만원` | `원`·`천원`·`백만원`·`억원` |
| `--statements` | `BS,CIS,SCE,CF` | 재무상태표·포괄손익·자본변동·현금흐름 중 선택 |
| `--out` | `<회사>_Raw_BSPL_<날짜>.csv` | 출력 경로 |

## 절차

1. 회사명이 모호하면 `resolve_company`로 6자리 종목코드를 먼저 확정하고, 확정한
   코드를 스크립트에 넘긴다.
2. 위 명령을 실행한다. 스크립트가 `fs_reports`를 직접 호출하므로 **응답을 도구로
   미리 가져오지 마라** — 보고서당 60KB, 전체 2MB가 넘어 컨텍스트만 낭비된다.
3. 표준출력에 찍힌 보고서 목록(접수번호·계정 수)을 사용자에게 그대로 전달한다.
4. "미포함 보고서 N건"이 나오면 더 필요한지 묻지 말고 그대로 보고한다 — 사용자가
   원하면 `--reports`를 올려 다시 실행한다.

## 결과 형태

보고서 하나가 9열 블록이고, 블록이 좌우로 이어진다. 블록 안은 표(재무상태표 →
포괄손익계산서 → 자본변동표 → 현금흐름표) 순서로 쌓이며, 표마다 자기 기간 헤더를
따로 갖는다.

기간 헤더가 표마다 다른 것은 DART 원본이 그렇기 때문이다:

- 재무상태표는 시점값이라 `제 36 기 1분기말` / `제 35 기말`
- 분기보고서의 손익계산서는 `3개월`과 `누적`을 나눠 싣고 전기 칸에 기간명이 없다
  (그래서 `전년동기 3개월` / `전년동기 누적`으로 표기된다)
- 사업보고서는 당기·전기·전전기 3개년

자본변동표는 자본 구성요소별 행렬이라 `세부` 열에 구성요소가 들어간다.

## 알아둘 것

- 계정 순서는 OpenDART 전체계정의 `ord` 순서다. DART 웹 뷰어의 들여쓰기 계층과는
  다르며(예: 자산총계가 유동자산보다 먼저 올 수 있다), 계정명·금액은 동일하다.
- 금액 원본 단위는 원이고 `--unit`으로 환산해 쓴다. 기본 백만원은 DART 뷰어 표기와
  맞춘 값이다.
- 사업연도(`bsns_year`)는 회계연도 기준이다. 2025년 사업보고서는 2026년 3월에
  접수되지만 `2025`로 잡힌다.

## 실패 처리

- **실행 환경 확인이 먼저다** — `${CLAUDE_PLUGIN_ROOT}`가 비어 있거나
  `scripts/build_raw_bspl.py`가 존재하지 않으면 이 스크립트를 아예 실행할 수 없는
  환경이다. claude.ai 챗의 "스킬" 기능은 플러그인의 개별 스킬 폴더만 올리고
  `scripts/`(스킬 폴더 밖의 공용 디렉터리)는 가져오지 않는다 — Claude Code와
  Cowork는 플러그인 전체를 마운트하므로 이 문제가 없다. 이 경우 즉시 §대안
  절차로 넘어가고, 원인을 사용자에게 그대로 보고한다(추측하지 말 것).
- `SKIPPER_API_KEY 또는 SKIPPER_ACCESS_TOKEN 환경변수가 비어 있습니다` → 이
  스크립트는 MCP 세션이 아니라 `/api/v1/tools/*` REST 엔드포인트를 직접
  호출하므로 둘 중 하나가 세션에 따로 있어야 한다. `SKIPPER_API_KEY`(정적 키,
  `support@skipperlabs.ai`에서 발급)가 만료 없이 반복 실행에 적합해 기본
  권장이다. MCP 커넥터를 OAuth로 연결해 둔 경우 그 액세스 토큰을
  `export SKIPPER_ACCESS_TOKEN="..."`로 넣어도 동작하지만, 토큰이 만료되면
  다시 발급받아 넣어야 한다.
- Cowork에서 실행 중인데 네트워크 오류(`... 호출 실패 — 네트워크 오류`)가 나면,
  Cowork 설정의 네트워크 허용목록(egress allowlist)에 `api.skipperlabs.ai`가
  추가돼 있는지 확인해 달라고 안내한다 — 비어 있으면 기본이 전체 차단이다.
- `조건에 맞는 전계정 재무제표 보고서가 없습니다` → 비상장이거나 유니버스 밖일 수
  있다. `dart_company`로 존재 여부를 확인하고 결과를 그대로 보고한다.
- 값을 지어내지 마라. 스크립트가 실패하면 실패했다고 보고한다.

## 대안 절차 — 스크립트를 실행할 수 없을 때

플러그인이 개별 스킬만 마운트된 환경(예: claude.ai 챗)에서는 위 스크립트를 실행할
수 없다. 이때는:

1. `fs_reports(query, meta_only=true)`로 보고서 목록(접수번호·사업연도·구분·계정 수)만
   먼저 가져와 사용자에게 그대로 전달한다.
2. 전체 계정 데이터가 필요하면, `fs_reports(query, meta_only=false)`가 그 회사의
   보고서 **전체**(현재 보고서 단위로 일부만 골라 받는 기능이 없다 — 최대 40여 건,
   ~2MB)를 한 번에 반환한다는 점을 먼저 알린다. 사용자가 동의하면 그대로 호출하고,
   받은 JSON을 표로 직접 정리해 전달한다.
3. "9열 블록 자동 조판(`build_raw_bspl.py`)은 스크립트가 실행되는 환경(Claude
   Code, 또는 네트워크 허용목록·`SKIPPER_API_KEY`가 설정된 Cowork)에서만
   가능하다"고 명시해 혼선을 줄인다.
