# Raw_부문별매출 — 보고서별 사업부문 공시 원자료

정기보고서마다 두 섹션을 뽑아 옆으로 나란히 붙이고, 그 아래에 XBRL 부문 팩트를
표로 덧붙인 CSV를 만든다.

- **2. 주요 제품 및 서비스** — 부문 설명, 주요 종속회사 현황
- **4. 매출 및 수주상황** — 사업부문별 매출액·영업이익·비율 표 (부문 표의 정본)

두 가지를 같이 넣는 이유: 원문 섹션은 DART 표 구조가 평문으로 눌려 있어 숫자
작업에 바로 못 쓴다. 반대로 XBRL 팩트는 표로 깔끔하지만 커버리지가 들쭉날쭉하다.
둘을 같은 파일에 두고 **교차 검증**하는 것이 이 시트의 용도다.

## 실행

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/build_raw_segment.py" "<회사명 또는 종목코드>" \
  --reports 5
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--reports N` | 5 | 최신순으로 붙일 정기보고서 개수 |
| `--out` | `<회사>_Raw_부문별매출_<날짜>.csv` | 출력 경로 |

## 절차

1. 회사명이 모호하면 `resolve_company`로 종목코드를 확정한 뒤 넘긴다.
2. 위 명령을 실행한다. 스크립트가 도구를 직접 호출하니 **섹션 원문을 도구로 미리
   가져오지 마라**.
3. 표준출력의 보고서 목록과 `XBRL 부문 팩트 N행`을 사용자에게 전달한다.
4. `주의: 부문 팩트가 비어 있습니다`가 뜨면 그 사실을 반드시 함께 보고한다 —
   숫자 작업은 원문 표를 직접 읽어야 한다는 뜻이다.

## 데이터 경로

`segment_series`를 먼저 쓰고, 그 도구가 없는 배포에서는 `list_disclosures`(정기공시)
+ `get_document(section='주요 제품')`로 폴백한다. 폴백이 걸리면 표준출력의 `출처:`에
그렇게 찍히므로, 사용자에게 보고할 때 어느 경로였는지 함께 적는다.

## 결과 형태

- 위쪽: 보고서 하나가 2열 블록(본문 1열 + 여백 1열), 좌우로 이어짐. 본문은 한국어
  문장 끝 기준으로 줄을 나눈다.
- 아래쪽: `사업연도 / 보고서 / 기간유형 / 축 / 부문 / 지표 / 금액(백만원)` 표.
  축은 사업부문·지역·제품으로 나뉜다.

## 알아둘 것

- 원문 섹션은 4,000자 안에서 잘릴 수 있다. 특정 보고서의 표 전체가 필요하면
  `get_document(rcept_no, section='매출')`로 따로 더 가져온다.
- **XBRL 부문 팩트와 원문 부문 표는 서로 다른 표일 수 있다.** 지주회사에서 흔하다 —
  예를 들어 SK(주)는 원문 "4. 매출 및 수주상황" 표가 투자부문·사업부문 2개인데,
  XBRL 부문 팩트의 멤버는 SK이노베이션·SK텔레콤 같은 종속회사별로 잡힌다. 팩트
  합계가 연결 매출과 크게 어긋나면 이 경우이니, **원문 표를 정본으로 삼는다.**
- 부문별 매출액·비중 표를 만드는 것이 목적이라면 `skipper:segment-summary` 스킬을 쓴다.
- 원문 표는 평문으로 눌려 있어 헤더와 값이 한 줄에 섞여 나온다. 숫자를 읽을 때는
  단위(백만원·천원)와 열 순서를 헤더 문구에서 먼저 확인한다.

## 실패 처리

- `SKIPPER_API_KEY 환경변수가 비어 있습니다` → 키 설정을 안내한다.
- `'주요 제품 및 서비스' 섹션이 있는 정기보고서를 찾지 못했습니다` → 상장 직후라
  정기보고서가 없거나 유니버스 밖일 수 있다. 사실대로 보고한다.
