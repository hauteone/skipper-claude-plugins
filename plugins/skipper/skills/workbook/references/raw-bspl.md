# Raw_BSPL — 보고서별 연결재무제표 원자료

정기보고서마다 "2. 연결재무제표"의 네 개 표를 통째로 뽑아 보고서 단위 블록으로
아래로 이어 붙인 CSV를 만든다. 보고서별 값을 따로 싣는 이유는 **같은 계정이
보고서마다 다르게 보고될 수 있기 때문**이다 — 재작성(restatement)을 잡으려면
기간별 최신값 하나가 아니라 보고서별 as-reported 값이 필요하다.

## 실행 — MCP로 데이터를 가져와 로컬에서 CSV만 만든다 (권장, 자격증명 불필요)

스크립트는 네트워크를 전혀 부르지 않는다 — `fs_reports` MCP 도구 호출은 에이전트가
하고, 스크립트는 그 결과를 CSV로 조판만 한다. API 키도, Cowork 네트워크
허용목록 설정도 필요 없다.

1. `fs_reports`를 직접 호출한다 — **`reports`·`fs_div`를 반드시 같이 넘겨서**
   응답 크기를 줄인다 (둘 다 생략하면 그 회사의 보고서 **전체** — 최대 수십 건,
   ~2MB — 가 그대로 컨텍스트에 실린다). 아래 3번의 `--reports`/`--fs-div`와
   같은 값을 준다. 예: `fs_reports(query="005930", reports=4, fs_div="CFS")`.
2. 받은 JSON 응답을 그대로 로컬 파일에 쓴다 (예: `/tmp/005930_fs_reports.json`).
3. 스크립트를 실행한다:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/build_raw_bspl.py" "<회사명 또는 종목코드>" \
  --from-json /tmp/005930_fs_reports.json --reports 4 --fs-div CFS --unit 백만원
```

4. 표준출력에 찍힌 보고서 목록(접수번호·계정 수)과 **보고서 간 대조 결과**를
   사용자에게 그대로 전달한다. 스크립트가 같은 기수가 두 보고서 이상에 실린
   값을 자동 대조해 "값 일치" 또는 "재작성 의심 N건"(계정·기수·보고서별 값)을
   찍는다 — 차이가 보고되면 값과 함께 알리되, 원인(재작성·재분류·정정)은 공시
   원문으로 확인하기 전에는 단정하지 않는다.
5. "미포함 보고서 N건"이 나오면 더 필요한지 묻지 말고 그대로 보고한다 — 사용자가
   더 원하면 1번부터 `reports` 값을 올려 반복한다.

옵션(스크립트 공통):

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--from-json PATH` | (없음) | `fs_reports` 응답 JSON 경로. `-`면 표준입력. 주면 네트워크·자격증명이 전혀 필요 없다 |
| `--reports N` | 4 | 최신순으로 붙일 보고서 개수 |
| `--fs-div` | `CFS` | `CFS`=연결, `OFS`=별도, `both`=둘 다 |
| `--unit` | `백만원` | `원`·`천원`·`백만원`·`억원` |
| `--statements` | `BS,CIS,SCE,CF` | 재무상태표·포괄손익·자본변동·현금흐름 중 선택 |
| `--out` | `<회사>_Raw_BSPL_<날짜>.csv` | 출력 경로 |

## 대안 — 스크립트가 fs_reports를 직접 호출하게 하기

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/build_raw_bspl.py" "<회사명 또는 종목코드>" \
  --reports 4 --fs-div CFS --unit 백만원
```

`--from-json`을 안 주면 스크립트가 `fs_reports`를 직접 호출한다 — 결과는 위와
같고 MCP 왕복 한 단계가 줄어들지만, 세션에 인증이 있어야 한다(SKILL.md §인증
참고). **이 경로를 쓸 때는 응답을 도구로 미리 가져오지 마라** — 스크립트가
알아서 부른다.

## 결과 형태

보고서 블록이 세로로 이어지는 단일 열 흐름이다. 블록마다 제목(회사·연도·보고서·
기준)·접수번호·단위 행이 오고, 그 아래 표(재무상태표 → 포괄손익계산서 →
자본변동표 → 현금흐름표) 순서로 쌓이며, 표마다 자기 기간 헤더를 따로 갖는다.
표 사이는 빈 행 1줄, 보고서 사이는 빈 행 2줄로 구분된다.

보고서끼리의 비교(재작성 탐지)는 CSV를 눈으로 대조하는 대신 스크립트가 수행한다
— 같은 기수("제 N 기…")가 여러 보고서에 실린 계정을 자동 대조해 결과를
표준출력으로 보고한다. '전기'·'전년동기' 같은 상대 라벨은 보고서마다 가리키는
기간이 달라 대조에서 제외된다.

기간 헤더가 표마다 다른 것은 DART 원본이 그렇기 때문이다:

- 재무상태표는 시점값이라 `제 36 기 1분기말` / `제 35 기말`
- 분기보고서의 손익계산서는 `3개월`과 `누적`을 나눠 싣고 전기 칸에 기간명이 없다
  (그래서 `전년동기 3개월` / `전년동기 누적`으로 표기된다)
- 사업보고서는 당기·전기·전전기 3개년

자본변동표는 자본 구성요소별 행렬이라 `세부` 열에 구성요소가 들어간다.

## 알아둘 것

- 계정 순서는 OpenDART 전체계정의 `ord` 순서다. DART 웹 뷰어의 들여쓰기 계층과는
  다르며(예: 자산총계가 유동자산보다 먼저 올 수 있다), 계정명·금액은 동일하다.
- 금액 원본 단위는 원이고 `--unit`으로 환산해 쓴다. 기본 백만원은 DART 뷰어 표기와
  맞춘 값이다.
- 사업연도(`bsns_year`)는 회계연도 기준이다. 2025년 사업보고서는 2026년 3월에
  접수되지만 `2025`로 잡힌다.

## 실패 처리 (시트 전용)

- `조건에 맞는 전계정 재무제표 보고서가 없습니다` → 비상장이거나 유니버스 밖일 수
  있다. `dart_company`로 존재 여부를 확인하고 결과를 그대로 보고한다.

환경·인증·Cowork 관련 공통 실패 처리는 SKILL.md를 따른다.
