# Raw_부문별매출 — 보고서별 사업부문 공시 원자료

정기보고서마다 두 섹션을 뽑아 옆으로 나란히 붙이고, 그 아래에 XBRL 부문 팩트를
표로 덧붙인 CSV를 만든다.

- **2. 주요 제품 및 서비스** — 부문 설명, 주요 종속회사 현황
- **4. 매출 및 수주상황** — 사업부문별 매출액·영업이익·비율 표 (부문 표의 정본)

두 가지를 같이 넣는 이유: 원문 섹션은 DART 표 구조가 평문으로 눌려 있어 숫자
작업에 바로 못 쓴다. 반대로 XBRL 팩트는 표로 깔끔하지만 커버리지가 들쭉날쭉하다.
둘을 같은 파일에 두고 **교차 검증**하는 것이 이 시트의 용도다.

## 실행

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/build_raw_segment.py" "<회사명 또는 종목코드>" \
  --reports 5
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--reports N` | 5 | 최신순으로 붙일 정기보고서 개수 |
| `--years N` | 5 | 팩트 표에 담을 연도 수 |
| `--axes` | `segment` | 팩트 축 (`segment,region,product` 쉼표 구분) |
| `--metrics` | `revenue` | 팩트 지표 (`revenue,operating_profit,assets,...`) |
| `--periods` | `FY,Q1,Q2,Q3,Q4` | 팩트 기간. `H1`·`9M`은 누적이라 분기 합과 겹치므로 기본에서 뺐다 |
| `--out` | `<회사>_Raw_부문별매출_<날짜>.csv` | 출력 경로 |

축·지표·기간 조합마다 한 번씩 조회하므로, 축이나 지표를 늘리면 호출 수가 곱으로
늘어난다. 필요한 것만 지정한다.

## 절차

1. 위 명령을 실행한다. 스크립트가 도구를 직접 호출하니 **섹션 원문을 도구로 미리
   가져오지 마라** (인증 필요 — SKILL.md §인증 참고).
2. 표준출력의 보고서 목록과 `XBRL 부문 팩트 N행`을 사용자에게 전달한다.
3. `주의: 부문 팩트가 비어 있습니다`가 뜨면 그 사실을 반드시 함께 보고한다 —
   숫자 작업은 원문 표를 직접 읽어야 한다는 뜻이다.
4. `경고: 기간에 따라 서로 다른 표가 채택된 조합이 있습니다`가 뜨면 반드시 함께
   보고한다. 표가 바뀐 경계에서는 증감률이 성립하지 않는다 (아래 참조).

## 데이터 경로

**원문 섹션**은 `segment_series`로 가져오고, 그 도구가 없는 배포에서는
`list_disclosures`(정기공시) + `get_document(section='주요 제품')`로 폴백한다.
폴백이 걸리면 표준출력의 `출처:`에 그렇게 찍히므로 어느 경로였는지 함께 적는다.

**숫자(팩트)**는 `GET /api/v1/revenue-segments`로 iceberg 원천에서 직접 받는다.
`segment_series`의 `xbrl_facts`는 쓰지 않는다 — 그쪽은 그래프 적재분이라 표(roleKey)와
연결/별도(fsDiv) 구분이 없어 한 부문이 여러 값으로 갈린다.

## 표(roleKey)를 확인해야 하는 이유

한 보고서 안에 부문 표가 여럿 있고(영업부문 표 / 매출부문 표 / 수익원천별 표),
표마다 같은 부문의 금액이 다르다. 서버가 조합마다 표를 하나로 고정해 주지만,
**연도가 바뀌면 채택되는 표도 바뀔 수 있다.** 그 경우 스크립트가 경고를 낸다.

표가 바뀐 경계에서 증감률을 계산하면 실제 사업 변화가 아니라 표 차이를 읽게 된다.
경고가 뜨면 원문 "4. 매출 및 수주상황" 표로 연결성을 확인하고, 이을 수 없으면
시계열을 끊어서 제시한다.

## 결과 형태

- 위쪽: 보고서 하나가 2열 블록(본문 1열 + 여백 1열), 좌우로 이어짐. 본문은 한국어
  문장 끝 기준으로 줄을 나눈다.
- 아래쪽: `연도 / 기간 / 기준 / 기간유형 / 축 / 부문 / 정규화명 / 지표 /
  금액(백만원) / 비고 / 표(roleKey)` 표.
  - `기준` = CFS(연결) / OFS(별도)
  - `정규화명` = 연도 간 시계열을 이을 때 쓰는 조인 키. 발행사가 해마다 표기를
    바꾸므로('카카오' ↔ '㈜카카오') 부문명이 아니라 이 값으로 잇는다.
  - `비고` = `유도값`(Q2·Q4는 누적 차감으로 계산됨) 또는
    `negative_derivation`(차감이 음수라 서버가 폐기 — 그 칸은 원문에서 읽어야 함)

## 알아둘 것

- 원문 섹션은 4,000자 안에서 잘릴 수 있다. 특정 보고서의 표 전체가 필요하면
  `get_document(rcept_no, section='매출')`로 따로 더 가져온다.
- **XBRL 부문 팩트와 원문 부문 표는 서로 다른 표일 수 있다.** 지주회사에서 흔하다 —
  예를 들어 SK(주)는 원문 "4. 매출 및 수주상황" 표가 투자부문·사업부문 2개인데,
  XBRL 부문 팩트의 멤버는 SK이노베이션·SK텔레콤 같은 종속회사별로 잡힌다. 팩트
  합계가 연결 매출과 크게 어긋나면 이 경우이니, **원문 표를 정본으로 삼는다.**
- 부문별 매출액·비중 표를 만드는 것이 목적이라면 `skipper:segment-summary` 스킬을 쓴다.
- 원문 표는 평문으로 눌려 있어 헤더와 값이 한 줄에 섞여 나온다. 숫자를 읽을 때는
  단위(백만원·천원)와 열 순서를 헤더 문구에서 먼저 확인한다.
