# QA: "한화오션의 과거 10년 수주잔고를 정리해 줘" (2026-08-13)

질문 하나를 실제 사용자 세션과 동일한 도구 흐름으로 실행해, 우리 MCP·스킬이
만들어내는 답변의 품질과 한계를 평가했다.

## 실행 흐름

1. `resolve_company` → 042660 한화오션 (exact) ✅
2. `hybrid_search` "수주잔고 추이" → 최근 수주 뉴스(KDDX 7.8조 등) + 리포트 청크 ✅
3. `search_research` → 키움·SK증권·유안타 수주잔고 차트/표 청크 ✅
4. `list_disclosures`(days=3800, 정기공시) → **최근 20건만 반환, FY2022 사업보고서까지** ⚠️
5. `get_document` 사업보고서 4건 × section='수주상황' → 수주잔고 표 정확 추출 ✅
6. `financial_notes` → 한화오션 XBRL 주석 미적재 (원문 발췌 폴백만) ⚠️
7. `dart_company` → 최근 1년 공시만 (과거 접수번호 확보 불가) ⚠️

## 판정: 부분 성공 (10년 중 정확 수치 4년)

"과거 10년"의 앞 6년(FY2016~FY2021, 대우조선해양 시절)은 **도구로 원문 접근이
불가능**하다. 리포트 차트 캡션의 정성 서술로만 보완 가능.

## 발견 사항

| # | 심각도 | 대상 | 내용 |
|---|---|---|---|
| F1 | 높음 | `list_disclosures` | 반환 상한(~20건) 때문에 days=3800을 줘도 FY2022 이전 정기공시에 도달 불가. 장기 시계열 질문의 1차 사료 6개년이 잘림. limit/pagination 또는 보고서유형 필터(사업보고서만) 필요 |
| F2 | 중간 | `get_document` | section 키워드 민감도 — '수주상황'은 컴팩트한 해당 섹션, '수주'는 100KB 덤프(챗 세션이면 컨텍스트 폭발). 도구 설명에 "목차의 정확한 섹션 제목을 쓰라" 가이드 필요 |
| F3 | 높음 | 리포트 figure 캡션 | 자동 생성 캡션의 단위 오독 위험 — 키움 차트 캡션 "2018~2020년 약 10,000억원 수준"은 축 단위(십억원)를 감안하면 실제 약 10조원. 캡션 수치를 그대로 인용하면 10배 오류. 수치는 표(kind:table)나 공시 원문만 인용하는 규율 필요 |
| F4 | 낮음 | `financial_notes` | 한화오션 XBRL 주석 미적재 — 주석 경로 부재 (원문 발췌 폴백은 동작) |
| F5 | 낮음 | `hybrid_search` | '수주잔고' 일반 키워드에 무관 종목(파두) 혼입 — 관련 뉴스·리포트는 상위에 잘 잡히므로 실사용 영향 제한적 |

## 권고

1. (서버) `list_disclosures`에 limit/pagination 또는 `report_type=사업보고서` 필터 추가 — F1 해소 시 10년 시계열 완주 가능.
2. (스킬) pe-research에 "리포트 figure 캡션의 수치는 인용 금지 — 표·공시 원문으로 교차 확인" 규율 추가 검토 (F3).
3. (도구 설명) get_document에 섹션 키워드는 목차 제목 그대로 쓰라는 문구 추가 (F2).
