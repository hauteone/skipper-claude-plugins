# QA: 한화오션 부문 XBRL — FY·Q2 조회 0건의 원인 (2026-08-16)

사용자 세션이 분기 부문 매출을 만들며 "XBRL 부문 팩트는 FY·Q2 조회가 0건이라
쓸 수 없었고, 원문 「4. 매출 및 수주상황」 표 6건에서 직접 읽어 환산"이라고
보고했다. 왜 0건인지 운영 데이터와 코드로 특정했다.

## 관측 (경로 명시)

- **REST 운영 조회**: `GET api.skipperlabs.ai/api/v1/revenue-segments/042660`
  (X-API-Key, axis=segment, metric=revenue, limit=6) — iceberg 웹 경로 아님.

| period | 결과 |
|---|---|
| FY | 0건 |
| H1 | 2026 CFS role=`default` → **기타부문 824억 한 줄만** |
| 9M | 0건 |
| Q1 | 2026 CFS role=`InformationForEachOperatingSegment…` → 상선 2.79조 + EP및특수선 0.53조 |
| Q2 / Q3 / Q4 | 0건 |

- **운영 iceberg MySQL 직조회** (read-only):
  - `financial_statements`: 042660의 2015~2026 정기보고서 44건 전부
    `segments_parsed_at` 마킹됨 (8/9~8/13 백필) — 파싱 미시도 아님.
  - `financial_statement_segments` (segment/revenue): **2026년 두 보고서에서만** 행 존재.
    - 2026 11013(1분기): q3m — `InformationForEach…` 표에 상선+EP및특수선 2행, `default`에 기타부문 1행
    - 2026 11012(반기, 8/12 접수): **ytd만 있고 q3m 없음**. 부문 3개가 표 3개에 한 줄씩 분산:
      상선→`DisclosureOfOperatingSegments2`, EP및특수선→`entity00111704_…`(자회사 분해 표),
      기타부문→`default`
    - 2025년 이하: 0행 (파싱 시도 완료 상태에서 0행 = **발행사 태깅 부재**, 적재 갭 아님)
  - `financial_statement_segment_quarters`(2층): 이 종목 0행 → Q1 응답은 1층 직접값 폴백.

## 원인 판정

1. **FY 0건** — FY는 사업보고서(11011) 연간 팩트에서만 나오는데, 부문 태깅이 있는
   사업보고서가 아직 없다 (태깅 시작이 2026.1Q 보고서부터, 2026 사업보고서는 2027.3월).
2. **Q2 0건** — 경로 두 개(반기보고서 2Q q3m 직접값 / H1−Q1 차감) 모두 불성립:
   반기보고서에 q3m 태깅이 없고, H1 누적은 표 3개에 분산돼 Q1의 상선·EP(다른 표)와
   같은 표 안에서 짝을 이루지 못한다.
3. 사용자 세션의 원문 폴백·3중 검산은 **의도된 동작** (segment-summary 스킬 규칙과 일치).

## H1 퇴화 응답(기타부문만)의 메커니즘 — 코드베이스 특정

두 저장소에 표 선택 로직이 따로 있고 정렬 순서가 다르다:

| 경로 | 코드 | 정렬 | H1 2026 예측 |
|---|---|---|---|
| **skipper-api REST** (이번 관측 경로) | `internal/service/segment_derive.go:128-142` `resolveSegYear` | 다항 분해 → **커버리지(보고서 수)** → IFRS8 rank | `default`(커버리지 2: 11013+11012) > 정본 표(각 1) → **기타부문만** = 관측 일치 |
| iceberg 2층 빌더/웹 | `segment_quarterly.rb` `pin_role` | **rank** → 슬롯 커버리지 → 이름 | `DisclosureOfOperatingSegments2`(rank 0) → 상선만 |

- 커버리지를 rank 앞에 둔 것은 skipper-api d334541의 **의도적 설계**
  (HD현대중공업 329180: 기간별 독립 선택으로 시계열이 표를 넘나들던 문제의 해법).
  이번 케이스는 그 휴리스틱의 함정: 요청 기간 슬롯에서 후보가 전부 단일 항목이면
  다항 분해 가드가 무력화되고, 두 보고서에 걸친 `default` 잔여행 표가 커버리지로 이긴다.
- 2층 0행은 iceberg 예측과 모순 아님: 핀 고정된 상선 표에 H1 한 줄뿐이라 분기 유도가
  전부 불성립(0행 저장)했거나 빌더 미실행 — 어느 쪽인지는 미검증 (아래 Gaps).

## 서버 개선 후보

1. **분산 태깅 병합 보정** — 한 보고서에서 부문들이 표 여러 개에 한 줄씩 흩어진 경우
   정규화명(`normalize_label`) 기준으로 합쳐 하나의 논리 표로 취급. 이번 반기보고서가
   정확히 그 케이스 (상선/EP및특수선/기타부문이 각각 다른 role_key). 양쪽 레이어 공통 적용.
2. **커버리지 휴리스틱의 퇴화표 함정 완화** (skipper-api) — 단일 항목 동률일 때 `default`
   role 페널티 또는 "연중 최대 분해 항목 수"를 커버리지 앞 동률 판정에 반영.

## Gaps (미검증)

- 운영 배포 바이너리가 로컬 origin/main과 동일하다는 직접 대조(이미지 태그↔커밋)는
  안 함 — 관측이 로컬 코드 예측과 정확히 일치하는 것이 간접 증거. 로컬 미푸시 커밋은
  세그먼트 무관 chore 1건(6107b0e).
- 2층 0행의 사유(유도 불성립 0행 저장 vs 빌더 미실행) 미특정 — 빌더 로그 또는
  로컬 재실행으로 구분 가능.
- 2026 반기보고서의 분산 태깅이 발행사 XBRL 원본 구조인지(파서가 만든 분리가 아닌지)는
  DART 원본 아카이브 미대조 — 파서 산출 role_key 구조상 원본 유래로 추정.
